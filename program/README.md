# BOSS 求职助手 · 程序本体

这个目录是整套系统里的**执行层**：登录、采集岗位、抓正文、解析简历、评分、写招呼语、发送、复盘，实际跑起来的是这里的代码。

它不预设“什么样的岗位适合你”。采集条件、评分标准、招呼语要求这些高度个人化的东西，由**用户和自己的 AI 对话对齐后写进来**，程序只负责按写进来的内容执行，并把每一步的实际输入和结果留档。

配套的 Skill 在仓库的 `skill/boss-career/`，它负责告诉用户 AI：什么时候该问什么、什么算已经生效、失败时怎么处理。

```
用户 ──对话── 用户 AI ──读写── 程序 ── 平台请求 ── BOSS
                 │                │
                 └── 读 Skill ────┴── 面板（用户看结果）
```

## 三个部分的分工

| 部分 | 位置 | 职责 |
|---|---|---|
| 执行层 | 本目录 | 数据源、模板、接口、台账。不猜用户偏好 |
| 方法层 | `../skill/boss-career/` | 引导用户 AI 与用户对齐方案、操作程序、判断生效边界 |
| 面板 | `boss_web/static/` | 只呈现结果：采到什么、评了多少分、文案长什么样、回复率如何 |

面板不是参数控制台。调优发生在用户和 AI 的对话里，改完再写回程序。

## 能做什么

| 环节 | 实现 |
|---|---|
| 登录 | 短信验证码 / APP 扫码；登录态存本地，滑块由用户本人完成 |
| 采集 | 按平台实际选项筛选：城市、关键词、职位类别、区/商圈、地铁线站、行业、公司规模、经验、学历、薪资档、融资阶段。多城市按「每城 × 每词」分别记游标 |
| 补正文 | 逐条抓岗位详情；共享请求节奏控制，遇到平台限制自动停批并保留现场 |
| 简历 | 上传（Word / PDF / Markdown / 文本）→ 结构化事实 → 版本管理；可选生成修改稿，原稿始终保留 |
| 评分 | 一次评分：候选人材料 + 个人标准 + 岗位 → 分数、理由、缺口；按分数线进候选池 |
| 招呼语 | 按岗位生成，引用候选人事实与 JD 对应关系；审核后回写，未审核不发 |
| 发送 | 用户在对话里授权范围与额度，后台执行器接管，逐条间隔发送 |
| 复盘 | 同步回复、按发送记录归档，区分新增回复与累计回复率 |
| 面试 | 按岗位出题，可绑定自定义出题模板 |

## 运行

环境：Python 3.10+、Chrome 或 Edge（取安全网关令牌要用真浏览器）。

```bash
python -m venv .venv
# Windows:  .venv\Scripts\activate
# macOS / Linux:  source .venv/bin/activate
pip install -r requirements.txt

python -m boss_web
# 默认 http://127.0.0.1:8787
```

首次打开是空工作区：登录 → 设采集条件 → 上传简历，之后按面板顺序往下走。

模型不是必需项。程序可以自己配一个 OpenAI 兼容接口做后台评分/写稿（「AI 与设置 → 模型与 API」），也可以完全交给用户 AI 在对话里做完再回写——两条路线共用同一份个人方案、同一套台账。

## 目录

```
boss_login/     登录、会话、扫码、本地凭证
boss_jobs/      岗位抓取、详情、请求节奏控制、安全网关令牌、本地存储
boss_filter/    平台筛选项目录（含职位类别、区/商圈、地铁）、写参校验
boss_core/      方案编译、快照、条件判定、薪资、策略、授权
boss_db/        SQLite 表结构与迁移
boss_web/       Web 服务、面板前端（static/）、接口（api/）、业务（services/）
workflow/       采集、补全文、写稿、发送、复盘等执行脚本
```

`CONTEXT.md` 是这套设计的词表：用户 AI、配套 Skill、个人方案、评分模型、运行结果、求职面板——几个容易混的概念在这里固定下来。

## 数据与隐私

- 所有运行数据在本机 `data/` 下的 SQLite 里：登录态、岗位、简历、评分、发送与回复记录。不上传到任何服务器（模型调用除外，见下）
- 模型 Key 只存本地，界面回显是打码值
- 简历、岗位正文在评分或写稿时会发到你自己配置的模型服务；用哪家由你决定
- 仓库的 `.gitignore` 已排除 `data/`、`workspace/`、`browser-profile/`、`logs/` 和所有数据库文件——运行时产生的数据不会被提交

## 关于自动更新

上游原版带一个「检查更新」：对着 Gitee 发行版比版本号，发现新版可以在应用内直接覆盖升级（见 `boss_web/services/update_check.py`、`updater.py`）。

**本项目已经改造过，不建议继续用它的自更新**——它对比的是上游发行版，覆盖下去会把本项目的改动冲掉。要么关掉更新检查，要么把更新源换成你自己的仓库。这一点尚未改动代码。
