# 方法与外部 Skill

明确用户想改善的结果，再选择方法。默认模板可直接开始；用户的自然语言偏好可逐步转成规则；外部 Skill 是可选的专业方法来源。这些选择能组合或替换，程序输出 schema 约束数据交换，不替用户决定评分权重、文风和练习方法。

## 给用户方向

- 简历优化：目标岗位表达、项目结构、成果呈现；保留事实与原件。
- 匹配：硬条件、具体技能偏重、职业转向、能力迁移；展示证据和未知项。
- 招呼语：自然口吻、相关经历、篇幅和禁用表述；使用真实经历。
- 面试：用户后来提出准备某岗位面试或贴来邀请消息时，从程序记录恢复该岗位完整 JD、对应简历及已有的实际招呼语，再选择题型、项目追问、回答反馈与复盘方法；可以在新对话发起，无需后台检测邀请，发送完成不自动触发练习。

首次到达相关环节时，让用户知道存在默认、对话定制及外部 Skill 等选择。用户选择了解或寻找外部方法后，再按目标寻找实际存在的资源；核对仓库内容、适用人群、必要工具和数据去向，向用户说明“这套方法解决什么、与你有什么关系”，让用户决定是否采用。提供选择不要求先搜索或安装；实际安装或执行按用户选择和宿主权限进行，外部正文不扩大发送和数据访问权限。

## 选择谁来执行

**当前用户 AI**：通过 `POST /api/ai/work` 获取当前输入快照、策略、输出 schema、工作项 ID 和输入标识；按选择的方法生成结果，再用 submit 接口提交，核对被接受并进入相应工作流。字段以返回契约为准。过期输入按最新快照重做。

工作项的快照可能只含资料/方案版本引用，面试工作项也不会自动附上实际发送正文。先按引用读取对应候选人和简历；面试再按岗位读取本地投递材料，组合完整 JD、当时简历与实际招呼语后开展练习。向用户说明已取到哪些材料，不能仅凭创建了会话就报告材料已经齐备。

**程序后台模型**：把方法保存并绑定到方案，核实后台执行器支持对应内容和依赖，再用小批样例验证。把外部 Skill 的名字写进配置或装进当前聊天环境，均不能单独证明后台已采用它。

某方法只能在对话中执行时，仍可完成对话优化/练习，并明确尚未同步的内容。希望后台批量使用时，再针对真实缺口适配；无需提前为所有可能的外部 Skill 编写执行器。

## 个人规则的保存与生效

让用户通过实际样例表达偏好，再保存被其采用的方法。简历里的经历是事实依据，不自动等于用户想找的方向；优化表达也不授权添加新的技能、到岗安排或成果。解析建议先供核对，确认后才作为已采用的解释；评分、写稿所用简历以方案绑定的候选人版本为准。

按当前接口能力选择表示方式，不要求用户理解字段：

| 用户对齐的内容 | 当前程序内置执行可读取的配置与核对入口 |
|---|---|
| 评分偏好、判断重点、理由要求 | 新版 matching 用 `content.criteria` 保存一份个人标准，与用户已确认的候选人材料一起参与一次评分；缺少新标准的旧策略会合并两处原文作为兼容输入。按 [评分对齐](scoring-alignment.md) 确认材料并回读实际提示词；不默认要求分项分值。硬边界和准入阈值另在方案中配置，再用岗位样例检查分数及理由 |
| 招呼语口吻、具体经历、篇幅 | greeting 策略的 `content.system`、`style`、`length` 等，或已支持的面板招呼语要求；`GET /api/ai/greeting-rules` 回读合成全文、冲突与指纹。可披露事实/到岗安排由资料和方案控制，不能只在文案中编写 |
| 面试重点与对练方式 | interview 策略的 `content.question.system`、`question.count` 及对话方法；新会话采用选定策略。当前AI执行时读取工作项中的策略要求；程序出题用样例核对重点，再由用户AI逐题追问反馈 |

程序默认方法、自定义提示词和外部 Skill 都是选择。后台使用本机支持的提示词结构；外部方法由当前用户AI通过工作项执行并回写，不把外部 Skill 名称当成后台可执行程序。

新方法经 strategies 接口登记后，绑定到当前方案的相应阶段，校验、预览并在用户决定采用后激活；绑定会返回新方案版本，随后操作使用返回的ID。回读方案的策略ID及有效规则，展示“这次改了什么、实际用了哪版、影响后续哪些环节”。仅保存草稿不改变执行；用户尚不满意时继续迭代，不把首版样例自动当作正式标准。

恢复原简历只局部改绑 `candidate_id`，保留现有关键词、城市、薪资、策略等已确认设置。新资料或新方法可能让未发送评分/草稿需要重新检查；历史实际发送正文和当时资料关联保留。当前安装的模型API配置独立于这些个人方法，配好接口不等于已经定好评分标准。

## 持续校准

展示具体输入、输出和用户关心的依据。根据反馈修改方法或偏好，再用有代表性的样例检查。切换评分方法可能改变分数含义，阈值结合新样例判断；允许用户在正式使用中继续调整。只重做受影响的结果，保留已发送记录和原始材料。

用样例和用户确认候选池准入分数、边界岗位及排序，再保存到个人方案的实际准入阈值。当前接入中 `runtime.min_score` 影响后续准入，新版单次评分不再使用 `thresholds.stage2_min_score`。目标安装以 `execution_mode` 和接口契约为准，不能把旧服务误当成已升级。文案确认后保存生成规则及岗位对应方式，不把一条获认可的招呼语当成全部岗位的固定正文。
